# Reports (all projects)

Reports for the ECSE 4320/6320 Advanced Computer Systems class-wide projects (due October 23, 2026, after a one-week extension).
Each report lives in `<project>/latex/`, next to its code, raw data and experiment scripts in
`<project>/code/`. This folder, `common/latex/`, holds the files the reports share.

| Report | Directory |
|---|---|
| Project 1 — SIMD Advantage Profiling | [`SIMD_Advantage_Profiling/latex/`](../../SIMD_Advantage_Profiling/latex/) |
| Project 2 — Cache & Memory Performance Profiling | [`Cache_and_Memory_Performance_Profiling/latex/`](../../Cache_and_Memory_Performance_Profiling/latex/) |
| Project 3 — SSD Performance Profiling | [`SSD_Performance_Profiling/latex/`](../../SSD_Performance_Profiling/latex/) |

## Layout

```
common/latex/
  preamble.tex            packages (siunitx, pgfplots, biblatex, cleveref, ...)
  macros.tex              draft/final switch, \todo, \tbd, \rubric, hypothesis box, knobs table, plot styles
  system_info.tex         \sys... macros for the environment table (generated by common/code/scripts/collect_env.sh)
  environment_table.tex   shared measurement-environment table
  references.bib
<project>/latex/
  main.tex                title, abstract, section order
  latexmkrc               pdflatex + biber, aux files in build/
  sections/NN_*.tex       one file per section; experiment sections map to rubric items
  data/                   processed CSVs synced from <project>/code (plotted directly with pgfplots)
```

## Building

From the repository root:

```bash
make reports      # all three, draft mode -> <project>/latex/<project>.pdf
make simd         # just one (also: memory, ssd)
make watch-simd   # continuous rebuild while writing
make final        # rubric boxes hidden; lists every leftover TODO / ?? / missing data file
```

Or run `latexmk` inside a project's `latex/` directory (editors such as VS Code LaTeX Workshop pick up
`latexmkrc` automatically).

**Draft mode** shows a blue rubric box at the top of each section. A missing data file shows as a
grey placeholder, so the report compiles before any data exists.

## VS Code

Open the repository root folder; the settings are in `.vscode/`.

- **Build:** saving any `.tex` file builds its report with `latexmk`, using that folder's `latexmkrc`.
  Every section file starts with `% !TeX root = ../main.tex`, so the right report is always built.
- **PDF side view:** <kbd>⌘⌥V</kbd> (LaTeX Workshop: View LaTeX PDF) opens `build/main.pdf` in a tab
  to the right and refreshes it after each build.
- **SyncTeX:** <kbd>⌘⌥J</kbd> jumps from the cursor to the PDF; <kbd>⌘</kbd>-click in the PDF jumps
  back to the source.
- **Final mode:** run "LaTeX Workshop: Build with recipe" and pick
  *latexmk (final: rubric boxes hidden, warns on TODOs)*.
- **C code:** use **Terminal → Run Build Task** (<kbd>⇧⌘B</kbd>) for the Makefile builds.

## Data flow

```bash
# from the repository root, on the test machine
common/code/scripts/collect_env.sh --tex > common/latex/system_info.tex
SIMD_Advantage_Profiling/code/scripts/run.sh baseline   # -> code/data/processed/baseline.csv
common/code/scripts/sync_data.sh                        # -> <project>/latex/data/*.csv
```

Figures use `\IfDataExists{<name>}{...}` around a pgfplots `tikzpicture` that reads
`data/<name>.csv`. The example plots assume columns such as `<value>_median`, `_q25` and `_q75`;
rename them to match whatever your processing writes.

Useful plot keys (defined in `common/latex/macros.tex`):

```latex
\begin{axis}[acs, xmode=log, log basis x=2, xlabel={$N$}, ylabel={ns/element}]
  \addplot+[iqr bars] table[x=n, y=ns_per_elem_median, iqr of=ns_per_elem,
                            only if={variant}{autovec}, only if={kernel}{saxpy}] {data/baseline.csv};
  \acsvline{32768}{L1d}
\end{axis}
```

## Writing workflow

1. **Before measuring**, fill in the section's `hypothesis` box and commit it. Git timestamps then
   show the hypothesis came first.
2. Run the experiment, sync data, and replace `\todo{}` / `\tbd` with results and analysis.
3. Keep `AI_USE_LOG.md` (repository root) current; summarize it in the AI-use section.
4. `make final` before submitting and resolve every warning it lists.
