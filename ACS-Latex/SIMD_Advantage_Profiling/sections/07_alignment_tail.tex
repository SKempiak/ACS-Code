\section{Alignment and Tail Handling}\label{sec:alignment}
\rubric{Alignment, tail, stride/gather studies}{20}{Quantified alignment, prologue/epilogue and masking
effects with a convincing explanation (with \cref{sec:stride}).}

\begin{hypothesis}
  A start address that is not \qty{32}{\byte}-aligned should force the \qty{256}{bit} loads to be
  unaligned and/or trigger a scalar peel prologue, costing a modest fixed overhead that is most
  visible at small $N$. Because this is a client Skylake core, unaligned \code{vmovups} that happen
  to stay within a cache line should be nearly free, so we expect the penalty to be small
  (tens of percent) and to recur with \qty{64}{\byte} period as the offset sweeps a cache line.
\end{hypothesis}
\begin{hypothesis}
  (For the extended sweep.) The \code{scalar} build issues \qty{4}{\byte}
  loads that never straddle a line, so it should be insensitive to the offset; \code{autovec}
  (\qty{16}{\byte} loads) should show a smaller penalty than \code{native}. With a DRAM-resident
  array the misalignment cost should disappear into the memory stall time for all builds. For short
  loops, the time per \emph{call} should grow in steps of \num{8} elements for \code{native} and
  \num{4} for \code{autovec} (one vector iteration per step), with the vectorized epilogue making the
  remainder cheap but not free.
\end{hypothesis}

\begin{knobs}
  Fixed       & kernel SAXPY; float32; unit stride \\
  Varied      & start offsets $0, 4, 8, \ldots, \qty{60}{\byte}$ (every multiple of \num{4}) at $N=\num{4096}$
                (L1-resident, isolates the prologue from bandwidth) and $N=\num{16777216}$
                (\qty{128}{\mebi\byte}, DRAM-resident); tail: every $N$ from \num{8} to \num{72} and
                $N$ stepping across an \num{8}-lane boundary near \num{4096}, offset $0$; all three
                build variants \\
  Script      & \code{SIMD_Advantage_Profiling/scripts/run.sh alignment} \\
\end{knobs}

\subsection{Analysis}
\emph{Misaligned starts, L1-resident} (\cref{fig:alignment}a). The penalty is real, it scales with
vector width, and it repeats with the load width. Native SAXPY runs at
\qtyrange{0.098}{0.100}{\nano\second} per element at offsets $0$ and \qty{32}{\byte} (both
\qty{32}{\byte}-aligned, since the base is \qty{64}{\byte}-aligned). Every other offset costs
\qtyrange{0.142}{0.143}{\nano\second} (\SI{+46}{\percent}) or, at \numlist{28;36;40;60}, up to
\qty{0.157}{\nano\second} (\SI{+60}{\percent}). \code{autovec} (\qty{16}{\byte} loads) is fast
exactly at the multiples of \num{16} (offsets $0$, \num{16}, \num{32}, \num{48}:
\qtyrange{0.191}{0.198}{\nano\second}) and \SIrange{13}{25}{\percent} slower elsewhere.
\code{scalar} varies by only \SI{1.0}{\percent} (\qtyrange{0.568}{0.573}{\nano\second}). This
ordering, native \SI{60}{\percent} > autovec \SI{25}{\percent} > scalar \SI{1}{\percent}, is what
cache-line splits predict. At a non-multiple-of-32 offset every second \qty{32}{\byte} load
straddles a \qty{64}{\byte} line, but only every fourth \qty{16}{\byte} load does, and a
\qty{4}{\byte} scalar load never does. GCC does not peel the loop to an aligned start
(\cref{sec:vectorization}), so every split load pays. The finer structure is not explained. Both vector builds have a
second level at offsets \numlist{28;36;40;60}: native is slower there (\SI{+60}{\percent} instead
of \SI{+46}{\percent}), and autovec is faster (\SI{+13}{\percent} instead of \SI{+25}{\percent}),
although counting split loads predicts the same number at all non-aligned offsets. Untested
hypothesis: an interaction between the split \emph{stores} to \code{y} and the following loads of
\code{x}, which have the same offset, for example in the store-to-load address check. Offsetting
\code{x} and \code{y} independently, which our harness does not support yet, would separate the
load and store effects. Every configuration's IQR is below
\SI{0.3}{\percent}.

\emph{DRAM-resident} (\cref{fig:alignment}b). At $N=\num{16777216}$ the penalty all but disappears.
The spread across offsets is \SI{6.1}{\percent} for native (\qtyrange{0.413}{0.438}{\nano\second}),
\SI{5.7}{\percent} for autovec and \SI{2.1}{\percent} for scalar, and every IQR is at most
\SI{2.9}{\percent}. Offset $0$ is among the fastest for both vector builds, but beyond that the
split-load pattern of L1 does not carry over. Native is equally fast at offset \num{24}, and
autovec's multiples of \num{16} are not consistently faster: offset \num{32} is among its slower
points. So the split-load cost hides under DRAM misses, and what remains is a few percent at most,
comparable to process-to-process variation.

\emph{Tails} (\cref{fig:tail}). Near $N=\num{4096}$ the time per element is flat across the
\num{8}-lane boundary (native \qtyrange{0.098}{0.103}{\nano\second}, autovec
\qtyrange{0.185}{0.198}{\nano\second}, scalar \qtyrange{0.57}{0.63}{\nano\second}). With
\numrange{1}{7} leftover elements out of \num{4096}, the remainder is invisible. Short loops expose
it. For $N=8\ldots72$, native's time per call is lowest at multiples of \num{8}
(\qty{13.7}{\nano\second} at $N=16$ rising steadily to \qty{16.7}{\nano\second} at $N=72$, only
$\approx\qty{0.05}{\nano\second}$ per element) and highest just below them, at $N\equiv7 \pmod 8$
typically \qtyrange{2}{3}{\nano\second} more. That sawtooth is the remainder path from the
disassembly (\cref{sec:vectorization}): one \qty{128}{bit} step for \num{4} elements and then up to
three scalar iterations. Native also has isolated outliers that the remainder does not explain:
\qty{24.8}{\nano\second} at $N=30$ (neighbours \qtyrange{15.8}{16.1}{\nano\second}),
\num{21.6} at $N=44$, \num{21.1} at $N=52$ and \qty{19.9}{\nano\second} at $N=50$.
\code{autovec} grows at $\approx\qty{0.15}{\nano\second}$ per element (outliers at $N=13$, \num{36}
and \num{56}) and \code{scalar} linearly at $\approx\qty{0.63}{\nano\second}$ per element (outliers
at, e.g., $N=11$, \num{30}, \num{44}, \num{61}). Each outlier is stable within the run (IQR below
\SI{1}{\percent}); that $N=30$ and \num{44} are slow in two builds suggests the per-$N$ array
placement rather than the kernel, an untested hypothesis. Every call also pays a fixed $\approx\qtyrange{10}{13}{\nano\second}$ (call,
loop setup and the run-time aliasing check of the versioned loop) before the first element. So the
per-element speedup of short loops is far below the $5.8\times$ at $N=\num{4096}$: native beats
scalar by only $1.11\times$ at $N=8$ and by $3.32\times$ at $N=72$. A masked tail (AVX2
\code{vmaskmovps}; this CPU has no AVX-512 mask registers) would replace the vector step and scalar
remainder by one masked iteration; we did not implement one.
