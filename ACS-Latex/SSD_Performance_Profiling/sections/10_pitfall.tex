\section{Misleading Setup}\label{sec:pitfall}
\rubric{AI-use transparency and pitfall analysis}{15}{Honest AI-use note and a meaningful misleading-setup
analysis (with \cref{sec:ai-use}).}

\begin{hypothesis}
  Dropping \code{O_DIRECT} lets the OS page cache serve repeated reads of the same region from RAM after
  the first pass, so a buffered benchmark will report throughput and latency that describe DRAM, not the
  SSD---orders of magnitude ``better'' than the real device, and entirely fictitious as a storage result.
\end{hypothesis}

\begin{knobs}
  Pitfall     & Buffered I/O measuring the page cache instead of the device \\
  Wrong setup & \qty{4}{\kibi\byte} sequential reads over a \qty{64}{\mebi\byte} region, \emph{no} \code{O_DIRECT} \\
  Right setup & Identical workload \emph{with} \code{O_DIRECT} (page cache bypassed) \\
  Fixed       & QD=1, 5 repetitions of \qty{4}{\second}; test file rewritten sequentially just before \\
  Script      & \code{SSD_Performance_Profiling/scripts/run.sh pitfall} \\
\end{knobs}

\subsection{Explanation}
\csvget\ssdBuf{pitfall}{mode=read-buffered}{iops_median}\csvget\ssdDir{pitfall}{mode=read}{iops_median}%
The buffered run reports \csvq{pitfall}{mode=read-buffered}{iops_median} IOPS at
\csvq{pitfall}{mode=read-buffered}{mibps_median}\,MiB/s and sub-microsecond latency, a
\ssdratio[0]{\ssdBuf}{\ssdDir}$\times$ inflation over the correct
\csvq{pitfall}{mode=read}{iops_median} IOPS. None of it is a storage measurement. After the first pass
the \qty{64}{\mebi\byte} region lives entirely in the page cache, so every later read is a
\code{memcpy} from RAM. The MiB/s figure is memory-copy bandwidth, and the latency is a cache hit, not an
NVMe access.

This is the easiest way to publish an impossibly fast SSD number, and an AI-generated benchmark falls
into it readily because omitting \code{O_DIRECT} is the \emph{default} behaviour of \code{open()}. Two
cheap detectors flag it in our data, and a third is expected to:
\begin{enumerate}
  \item The throughput exceeds the \qty{3756}{\mebi\byte\per\second} PCIe~3.0~$\times$4 link ceiling
        measured from sysfs (\cref{sec:method}). No device result can do that.
  \item Sub-microsecond \enquote{storage} latency is physically impossible for NAND flash.
  \item \emph{Proposed, not demonstrated here:} the number should depend on the \emph{region size},
        collapsing towards device speed once the region no longer fits in free RAM, which a true device
        result would not do. We ran the buffered path only on a \qty{64}{\mebi\byte} region, far below
        the host's \qty{63}{\gibi\byte} of RAM, so this detector is an expectation that we did not test.
\end{enumerate}

The methodology avoids the trap by construction. \code{O_DIRECT} is the default for every real run, and
the buffered path exists only to produce this comparison. \code{make test} also asserts that buffered
re-reads are more than $5\times$ faster than direct ones on the scratch filesystem, which proves the
cache is actually bypassed. Two related traps are covered elsewhere. A wrong effective queue depth is
caught by $L/\text{QD}$ in \cref{tab:littles-law}. Insufficient or wrong-order preconditioning, which
cut a \enquote{sequential} read to a sixth of its true speed in our pilot, is covered in
\cref{sec:layout}.
