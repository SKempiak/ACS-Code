\section{Validation and Sanity Checks}\label{sec:validation}

\code{make -C SSD_Performance_Profiling test} (\code{scripts/validate.sh}) checks that the benchmark
measures the SSD and not an artifact. It writes one \qty{64}{\mebi\byte} scratch file and deletes it.
\begin{itemize}
  \item \textbf{Safety gate.} \code{safety.sh} refuses both block devices, a symlink to \code{/dev/sda}
        inside the scratch directory, a directory, a path outside it (\code{/etc/passwd}), a mountpoint
        (\code{/}), and scratch directories at \code{/}, \code{\$HOME}, a filesystem root
        (\code{/dev/shm}) or not owned by the user (\code{/usr/share}); each test checks that the refusal
        names the intended rule. \code{blkbench} independently refuses a directory and a symlink.
  \item \textbf{Incompressible data.} The preconditioned file does not shrink under \code{gzip -1}.
  \item \textbf{Physical orderings.} \qty{128}{\kibi\byte} sequential beats \qty{4}{\kibi\byte} random
        throughput, and QD 1$\to$8 raises $L=\lambda W$ without exceeding QD (\cref{sec:queue-depth}).
  \item \textbf{Direct I/O is real.} \csvget\ssdVb{pitfall}{mode=read-buffered}{iops_median}%
        \csvget\ssdVd{pitfall}{mode=read}{iops_median}\csvget\ssdVr{zero_queue}{mode=read,pattern=rand}{iops_median}%
        The \code{--buffered} path reaches \ssdratio[0]{\ssdVb}{\ssdVd}$\times$ the sequential and
        \ssdratio[0]{\ssdVb}{\ssdVr}$\times$ the random \code{O_DIRECT} IOPS (\cref{tab:pitfall}), so the real
        runs bypass the page cache; \code{make test} asserts a gap of more than $5\times$.
  \item \textbf{Interface ceiling and identity.} No result may exceed the
        \qty{3756}{\mebi\byte\per\second} link (the highest,
        \csvq{block_size}{bs=65536,pattern=seq,mode=read,qd=32}{mibps_median}\,MiB/s, does not), and every
        \code{env.txt} records the parent disk, \code{rotational}=0, model, firmware and link.
\end{itemize}
\code{iostat} and \code{perf} are unavailable, so effective queue depth is checked in-band
(\cref{tab:littles-law}).

\subsection{Cross-check against FIO}\label{sec:fio-check}
\code{run.sh fio_check} runs seven points (QD=1 and 32; reads and writes; \qty{4}{\kibi\byte} random and
\qty{128}{\kibi\byte} sequential) through both engines, alternating them repetition by repetition. FIO's
\code{lat} percentiles measure the same submit$\to$completion time (log-bucketed, \ensuremath{\sim}\qty{3}{\percent}
bin error). We treat agreement within \qty{10}{\percent} in IOPS and p50 as validation
(\cref{tab:fio-check}).

\textbf{Reads agree:} IOPS ratios of 0.983--1.006 and p50 within \qty{1}{\percent}. (The two
\qty{128}{\kibi\byte} sequential points ran at only \ensuremath{\sim}\qty{225}{\mebi\byte\per\second} in
both engines because \code{fio_check} followed \code{layout} without a re-fill, since fixed; they
measured the fragmented layout of \cref{sec:layout}.)

\textbf{Writes vary more, mostly with drive state.} The lean-run write points give ratios of
\csvq[3]{fio_compare}{mode=write,pattern=seq,qd=1}{iops_ratio} (sequential),
\csvq[3]{fio_compare}{mode=write,pattern=rand,qd=1}{iops_ratio} and
\csvq[3]{fio_compare}{mode=write,pattern=rand,qd=32}{iops_ratio} (random, QD=1 and 32), with p50 within
\qty{1}{\micro\second}. In \cref{tab:fio-order}, position within a pair moves the sequential write from
\csvq{fio_order}{experiment=blkbench_1st,mode=write,pattern=seq}{iops_median} to
\csvq{fio_order}{experiment=blkbench_2nd,mode=write,pattern=seq}{iops_median} IOPS for the same engine,
more than the engine gap, and the QD=32 random-write ratio flipped from 0.78 in the original run, which
a fixed engine bias would not do. FIO's consistently slower QD=1 random write (also 0.93
originally) may reflect a small per-I/O host cost. We give write numbers from either engine a
\ensuremath{\sim}\qty{15}{\percent} uncertainty.
