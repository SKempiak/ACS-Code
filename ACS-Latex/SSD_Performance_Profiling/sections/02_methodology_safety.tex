The machine has two drives: this Micron NVMe SSD and a \qty{2}{\tera\byte} SATA HDD (\code{/dev/sda},
mounted at \code{/data}). The scratch directory is placed on the SSD's filesystem. Each run's
\code{env.txt} resolves the scratch filesystem's partition to its parent disk
(\code{nvme0n1p3}$\to$\code{nvme0n1}) and records that disk's \code{rotational} flag (0), model,
firmware, PCIe link and temperature, so a run can never be silently mislabelled
(\cref{sec:ai-use} describes how this check once failed).

\subsection{Data-loss safeguards}
\begin{itemize}
  \item \textbf{Targets.} Only disposable files (\code{testfile.bin}, \code{bigfile.bin}) in a dedicated
        scratch directory are ever written; nothing else on the SSD is touched. Both files are deleted
        when \code{run.sh} exits, including on interrupt.
  \item \textbf{Gate.} \code{scripts/safety.sh} runs before every experiment. It hard-refuses a block or
        character device (including through a symlink), a mountpoint, a directory, any path outside the
        scratch directory, and a target without enough free space. \code{scripts/validate.sh}
        (\code{make test}) verifies that it refuses \code{/dev/nvme0n1} and \code{/dev/sda}, a symlink
        to \code{/dev/sda}, \code{/etc/passwd} and \code{/}. These checks only \code{stat} the paths and
        never open them.
  \item \textbf{Benchmark.} \code{blkbench} \code{lstat}s its target \emph{before} opening it, refuses
        anything that is not a regular file, and opens with \code{O_NOFOLLOW}. No raw device or
        partition is ever opened.
  \item \textbf{Space.} The large device-state file (\qty{60}{\gibi\byte} here) is refused unless the filesystem
        keeps at least \qty{10}{\gibi\byte} free after creating it.
\end{itemize}

\subsection{I/O engines and configuration}
The primary engine is \code{build/blkbench}, a small O\_DIRECT benchmark built on Linux \code{libaio},
the same asynchronous engine as FIO's \code{libaio} ioengine \cite{axboe_fio}. It keeps exactly QD
requests in flight in a closed loop: every completion is immediately replaced. It records the
submit-to-completion latency of every I/O. FIO 3.42 runs the same points through
\code{fio/job.fio} (\code{libaio}, \code{direct=1}, total-latency percentiles), and
\cref{sec:validation} compares the two engines. \code{ENGINE=fio} routes every standard sweep through
FIO instead.
\begin{knobs}
  Engine          & \code{libaio}; \code{O_DIRECT} (page cache bypassed); 4\,KiB-aligned buffers and
                    block-aligned offsets; 64-bit uniform random offsets (splitmix64) \\
  Timing          & \qty{4}{\second} per repetition (\qty{6}{\second} for tail runs). Points that write
                    also stop after \qty{256}{\mebi\byte} per repetition, which bounds the bytes written
                    (\cref{tab:budget}). No separate ramp: preconditioning absorbs warm-up \\
  Repetitions     & 5 per point (3 for the block-size write points, also to bound bytes written);
                    figures and tables show the median with inter-quartile-range (IQR) bars \\
  Data pattern    & incompressible: every write buffer is filled once, before timing, from an
                    xorshift64* generator seeded per queue slot; the preconditioning pass uses the same
                    generator. \code{make test} checks that \code{gzip} cannot compress the result \\
  Latency metric  & per-I/O submit$\to$completion latency; p50/p95/p99/p99.9 from the full sorted
                    sample, with no reservoir truncation \\
  Preconditioning & before each experiment, one sequential O\_DIRECT write pass over the
                    \code{fallocate}d test file; repeated before every \emph{sequential-read} group
                    because random writes scatter the physical layout (\cref{sec:device-state}) \\
  Temperature     & NVMe composite temperature recorded with every repetition (\code{temp_c}) \\
  Driver          & \code{SSD_Performance_Profiling/scripts/run.sh}; benchmark \code{src/blkbench.c} \\
\end{knobs}
Because the issuing thread only submits and reaps completions, one thread can keep the device's queue
full. The Little's-Law check in \cref{sec:queue-depth} shows where this stops being true.

\subsection{Execution and run order}
The timed runs were executed by the author in a terminal, using the scripts described here, with the
CPU governor at \code{performance}, turbo off and SMT off. \code{run.sh all} ran the experiments in the
order of \cref{tab:budget} from 10:32 to 10:54. \code{SUSTAIN_GIB=60 run.sh device_state} followed
immediately, from 10:54 to 11:23. The drive's state carries over from one experiment to the next, and
nothing in between trims or idles it: the SLC-cache fill level and the background folding/GC backlog
are both inherited. Several results below depend on this, and each says so: the write collapse in
\cref{sec:block-size}, the tail runs in \cref{sec:tail}, and the whole of \cref{sec:device-state}.
