\section{TLB-Miss Impact}\label{sec:tlb}

\begin{hypothesis}
  With \qty{4}{\kibi\byte} pages, a dependent access to a random page should cost extra once the number
  of pages touched exceeds the L1 dTLB (64 entries) and again past the second-level TLB (1536 entries,
  \ensuremath{\approx}\qty{6}{\mebi\byte} of reach), where every access needs a page walk. With
  \qty{2}{\mebi\byte} pages one entry covers 512$\times$ more memory, so the same page counts should need
  no walks and the extra latency should vanish.
\end{hypothesis}

\begin{knobs}
  Chase        & one node per \qty{4}{\kibi\byte} page (node stride \qty{4160}{\byte} = page + one line, so nodes fall into different cache sets); random order; 16--65536 pages \\
  SAXPY        & random-order $y_i = a\,x_i + y_i$, $N = 2^{18}\ldots2^{24}$ \\
  Varied       & page size: \qty{4}{\kibi\byte} (\code{MADV_NOHUGEPAGE}) vs.\ \qty{2}{\mebi\byte} transparent huge pages (\code{MADV_HUGEPAGE}), both set before first touch; the chase also uses reserved \code{hugetlbfs} \qty{2}{\mebi\byte} pages (\code{MAP_HUGETLB}) \\
  Verification & \code{AnonHugePages} per run; dTLB-walk counter per access \\
  Script       & \code{Cache_and_Memory_Performance_Profiling/scripts/run.sh tlb} \\
\end{knobs}

The page-stride chase is designed so that page size is the \emph{only} difference between the two
curves: both touch the same number of cache lines (one per page, so the cache footprint is $N$ lines),
and the one-line stagger avoids every node mapping to the same cache set. Any latency gap is therefore
TLB reach and page-walk cost.

\subsection{Analysis}
The curves show both TLB levels as separate cliffs (\cref{fig:tlb}). Up to 64 pages both page sizes cost
the same (\valqty{tlb_4k_64_ns}{\nano\second} vs.\ \valqty{tlb_huge_64_ns}{\nano\second}). At 128 pages the
\qty{4}{\kibi\byte} chase jumps to \valqty{tlb_4k_128_ns}{\nano\second} while the \qty{2}{\mebi\byte} chase
stays at \valqty{tlb_huge_128_ns}{\nano\second}, with zero page walks in both. The
\valqty{tlb_gap_128_ns}{\nano\second} (\valnum{tlb_gap_128_cyc}~cycles) gap is the cost of missing the
64-entry L1 dTLB and hitting the second-level TLB. Near the STLB capacity walks begin
(\val{tlb_4k_1536_dtlb} per access at 1536 pages), and at 2048 pages every \qty{4}{\kibi\byte} access walks
(\val{tlb_4k_2048_dtlb} walks per access): \valqty{tlb_4k_2048_ns}{\nano\second} against
\valqty{tlb_huge_2048_ns}{\nano\second}, a \valqty{tlb_gap_2048_ns}{\nano\second} (\valnum{tlb_gap_2048_cyc}-cycle)
page-walk penalty while the page-table entries still hit in cache. Past 4096 pages the cache footprint
itself leaves L2 (4096 lines = \qty{256}{\kibi\byte}), raising both curves---the huge-page chase rises to
\valqty{tlb_huge_4096_ns}{\nano\second}---so only the gap is attributed to the TLB. That gap grows again
as the page tables outgrow the caches: \valqty{tlb_gap_16384_ns}{\nano\second} at 16384 pages and
\valqty{tlb_gap_65536_ns}{\nano\second} at 65536 pages (\valqty{tlb_4k_65536_ns}{\nano\second} vs.\
\valqty{tlb_huge_65536_ns}{\nano\second}, \val{tlb_ratio_65536}$\times$). With \qty{2}{\mebi\byte} pages the
walk counter stays at \val{tlb_huge_65536_dtlb} even at 65536 pages.

For random SAXPY (\cref{tab:tlb-saxpy}) at $N=2^{24}$, \qty{2}{\mebi\byte} pages cut page walks from \val{tlbs_4k_dtlb} to
\val{tlbs_huge_dtlb} per element and runtime from \valqty{tlbs_4k_ns}{\nano\second} (this run; the separate
\code{cache_miss} run of \cref{sec:cache-miss} measured \valqty{cm_rand_max_ns}{\nano\second}) to
\valqty{tlbs_huge_ns}{\nano\second} per element, a \val{tlbs_speedup}$\times$ speedup, a little below the
\val{tlb_ratio_65536}$\times$ of the dependent chase. Overlapping independent misses hides only a small part
of the walks: each walk adds dependent page-table reads in front of its data miss. The largest speedup in
the sweep is at $N=2^{20}$, where the footprint equals the L3: the \qty{2}{\mebi\byte}-page data still mostly
hit in the L3, while the \qty{4}{\kibi\byte} pages already need about one walk per element
(\cref{sec:cache-miss}).

\paragraph{Two huge-page mechanisms agree.} Reserved \code{hugetlbfs} pages (\code{MAP_HUGETLB}, from the
1024 pages the user set aside) give the same chase latency as transparent huge pages at every size
(\valqty{tlb_hugetlb_4096_ns}{\nano\second} vs.\ \valqty{tlb_huge_4096_ns}{\nano\second} at 4096 pages,
\valqty{tlb_hugetlb_65536_ns}{\nano\second} vs.\ \valqty{tlb_huge_65536_ns}{\nano\second} at 65536), with zero
walks. A \code{MAP_HUGETLB} mapping either gets reserved pages or fails, so no grant check is needed
(these pages are not counted in \code{AnonHugePages}). The THP result is therefore not an artifact of how
the kernel assembled the pages.

\paragraph{Huge pages are verified, not assumed.} Requesting huge pages does not guarantee them: a
benchmark that only asks for THP can silently run on \qty{4}{\kibi\byte} pages and report ``no effect''
(\cref{sec:anomalies}). The benchmarks map \qty{2}{\mebi\byte}-aligned regions and call \code{madvise} before the
first touch; each row records the granted \code{AnonHugePages} (summarised in the run's
\code{anon_thp.txt}), \code{validate.sh} checks the grant before each experiment, and the dTLB-walk counter
independently confirms the page size in effect. In this run every ``huge'' configuration was
fully backed: \code{AnonHugePages} equals the buffer size at every point (for example
\qty{266240}{\kibi\byte} for the 65536-page chase, and \qty{327680}{\kibi\byte} for SAXPY at $N=2^{24}$,
i.e.\ $x$, $y$ and the index array), and every \qty{4}{\kibi\byte} row records \qty{0}{\kibi\byte}.
