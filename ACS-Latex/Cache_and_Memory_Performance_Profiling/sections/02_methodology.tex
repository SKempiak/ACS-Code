All measurements were taken on the desktop system in \cref{tab:environment}: a ten-core Intel
i9-10900F (Comet Lake, Skylake-family core) with per-core \qty{32}{\kibi\byte} L1d and
\qty{256}{\kibi\byte} L2, a shared \qty{20}{\mebi\byte} L3, and DDR4 memory on one NUMA node. The table is
generated by \code{scripts/collect_env.sh} on the test host; each raw-data directory also stores its own
snapshot (\code{env.txt}) taken immediately before that experiment, so the settings of every figure are on
record even if the machine changes later.

\subsection{Tools}
All benchmarks share the harness in \code{ACS-Code/common} (monotonic raw timer, CPU pinning) plus a
project header \code{src/memprof.h} (page-policy allocation, ring generators, counters), and raw
per-repetition rows are reduced by \code{tools/summarize} (median and inter-quartile range).
\code{scripts/derive.py} then computes every derived number quoted in the text (plateaus, knee, Little's
Law, AMAT fit) into \code{summary.csv}; the report reads those values directly, so no number in the prose is
copied by hand.
\begin{knobs}
  \code{mem_latency}   & single-thread pointer-chase latency: working-set size, access size, node stride, page size, ring generator, timer, counters \\
  \code{mem_bandwidth} & streaming bandwidth with $T$ pinned threads: read/write/copy/triad/rwmix, access-size blocks, byte stride \\
  \code{mem_loaded}    & loaded latency: $T$ load-generator cores (stream, rwmix, or $k$ independent chases) plus a concurrent latency probe \\
  \code{kernel_miss}   & SAXPY loop whose footprint, order and page size vary, with counters \\
  \code{clock_check}   & diagnostic: fixed core clock vs.\ wall time lost by a pinned thread, idle DRAM traffic \\
  Core counters        & \code{perf_event_open(2)} called directly, per thread, user space only \cite{linux_perf} \\
  DRAM counters        & uncore memory-controller events \code{data_reads}/\code{data_writes}, system-wide \\
  Intel MLC            & v3.13, run as a normal user (\code{run.sh mlc}) \cite{intel_mlc} \\
\end{knobs}
\code{perf} (\sysPerf) is installed, but we want counts confined to the timed region of each
repetition, so the benchmarks call \code{perf_event_open(2)} themselves, enable the counters immediately
before each timed loop and read them immediately after it. Core events are counted for the measuring
thread in user mode only (\code{exclude_kernel=1}): cycles, instructions, L1D read misses, LLC read
references and misses, and dTLB read misses (completed page walks). They are opened independently so the
kernel may multiplex them; counts are scaled by \code{time_enabled/time_running} and the smallest running
fraction is recorded per row (\code{ctr_cover}). DRAM traffic is read from the client uncore
memory-controller PMU (\code{uncore_imc}: \code{data_reads}, \code{data_writes}, one count per
\qty{64}{\byte} line, scaled by the PMU's \code{.scale} files), opened system-wide on CPU~0 around the same
timed windows in \code{mem_loaded}, \code{mem_bandwidth} and \code{clock_check}. System-wide counting
needs \code{perf_event_paranoid}~$\le 0$, which the user set for these runs. Because the counts include all
traffic in the machine, the background of an idle system is measured separately (\code{clock_check}) and
quoted next to every result. Intel MLC v3.13 provides the external cross-check
(\cref{sec:validation}). Without root it cannot switch off the hardware prefetchers, so it runs with
\code{-e} (prefetchers left on) and \code{-r} (random access for the latency thread). MLC reports MB/s
($10^6$\,B/s); we convert to GiB/s ($2^{30}$\,B/s) wherever we compare.

\subsection{Controls}
\begin{itemize}
  \item \textbf{Pinning and isolation:} \acspinning. SMT: \sysSMT. The machine is otherwise idle and
        experiments are run one at a time. All data in this report were collected on 2026-10-21,
        20:22--20:39, in one \code{run.sh all} invocation (all experiments, MLC and \code{clock_check}).
  \item \textbf{Frequency:} governor \sysGovernor, turbo \sysTurbo, so the core runs at its fixed
        \qty{2.8}{\giga\hertz} base clock (equal to the TSC rate). Cycle figures are
        ns~$\times$~\valqty{zq_ghz}{\giga\hertz}. Two independent checks agree. User-mode cycles divided by
        wall time over the timed windows give a median of \valqty{ws_ctr_ghz}{\giga\hertz}. The in-process
        add-chain probe logged by every run reads \val{probe_st_min}--\valqty{probe_st_max}{\giga\hertz} in all
        \val{probe_st_n} single-thread repetitions (\val{probe_ld_min}--\valqty{probe_ld_max}{\giga\hertz} in the
        \code{mem_loaded} runs, where it runs just after nine generator threads are started).
        The probe is still not used for conversion: in an earlier run it was disturbed by an ACPI event
        storm (\cref{sec:anomalies}).
  \item \textbf{Interference:} the ACPI general-purpose event that caused that storm (GPE~0x42) was masked
        for these runs; its count did not change during the experiments. In \code{clock_check}, a
        pinned thread kept \val{cc_userfrac_min}--\val{cc_userfrac} of the wall time.
  \item \textbf{Pages:} every buffer is a \qty{2}{\mebi\byte}-aligned anonymous mapping whose page size is
        chosen by \code{madvise} \emph{before first touch}: \code{MADV_HUGEPAGE} for ``huge'' and
        \code{MADV_NOHUGEPAGE} for ``4k''. The second is essential because THP is \sysHugePages{}: without
        it a ``\qty{4}{\kibi\byte}'' baseline can silently receive huge pages. Each run records the
        \code{AnonHugePages} actually granted (from \code{/proc/self/smaps_rollup}).
  \item \textbf{Pre-faulting and warm-up:} every buffer is written once to fault in its pages, then the
        ring or stream is traversed (or one untimed repetition is run) before timing, so neither page
        faults nor cold-cache effects fall inside the timed region.
  \item \textbf{Repetitions:} 8 per point; figures show the median with inter-quartile-range error bars.
  \item \textbf{Timing:} each timed interval is calibrated to $\geq$\qtyrange{40}{200}{\milli\second},
        far above the timer resolution, so timer overhead is negligible. The loaded-latency windows read
        generator progress counters at the start and end of the \emph{same} interval in which the probe
        runs, so throughput and latency describe the same moment.
  \item \textbf{Code version:} the runs were started from a working tree on top of commit \code{29b8630}
        with uncommitted changes (\code{build.txt} records 37 changed paths). The measured sources,
        scripts, Makefile, shared harness and \code{tools/summarize} are byte-identical to those committed
        afterwards in \code{b00db66}. We verified this with \code{git diff b00db66}, which was empty
        for these paths before the later post-processing-only edits to \code{run.sh} and
        \code{derive.py}, and from the file times: every source was last modified before the binaries were
        rebuilt at 20:15, and the run started at 20:22. \code{run.sh} now warns loudly when the tree is
        dirty and records a hash of the uncommitted code diff in \code{build.txt}.
  \item \textbf{Provenance:} each \code{data/raw/<experiment>/<timestamp>/} directory holds the raw rows,
        \code{env.txt}, \code{build.txt} (git commit, compiler, flags, THP and counter settings),
        \code{commands.txt} (every command line) and \code{validate.txt} (the sanity gate of
        \cref{sec:validation}, run immediately before the experiment).
\end{itemize}
