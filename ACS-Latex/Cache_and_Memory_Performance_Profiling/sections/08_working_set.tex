\section{Working-Set Sweep}\label{sec:working-set}
\rubric{Working-set, cache and TLB analysis}{35}{Counters and performance correlated correctly (with
\cref{sec:cache-miss,sec:tlb}).}

\begin{hypothesis}
  Pointer-chase latency should trace the capacity staircase: flat while the set fits in L1
  (\qty{32}{\kibi\byte}), a step up through the \qty{256}{\kibi\byte} L2, a wider plateau across the
  \qty{20}{\mebi\byte} L3, and a final jump to the DRAM latency once the set exceeds LLC. Transitions
  should be gradual, not sharp, because of set-associativity and prefetcher spill.
\end{hypothesis}

  Fixed       & 1 thread pinned to CPU~2; random pointer chase; one node per \qty{64}{\byte} line; base pages \\
  Varied      & working-set size from \qty{8}{\kibi\byte} to \qty{512}{\mebi\byte} \\
  Script      & \code{Cache_and_Memory_Performance_Profiling/scripts/run.sh latency} \\
\end{knobs}

\subsection{Analysis}
The curve has four clear regimes separated at the marked capacities. It is flat at
\ensuremath{\sim}\qty{1}{\nano\second} up to \qty{32}{\kibi\byte} (L1), rises through
\qtyrange{3}{4}{\nano\second} across the L2 region, sits at \qtyrange{10}{23}{\nano\second} while the set
is LLC-resident, and saturates near \qty{84}{\nano\second} once it exceeds \qty{20}{\mebi\byte}. The
transitions are gradual rather than step functions: associativity means some lines spill a level early,
and the L2$\to$L3 shoulder near \qty{2}{\mebi\byte} shows the adjacent-line/stream prefetchers partly
hiding L3 latency until the set is several times the L2 size. This staircase is the direct input to the
AMAT model in \cref{sec:cache-miss}; the per-level plateaus here are the $t_{\text{L1}} \ldots
t_{\text{DRAM}}$ terms.
