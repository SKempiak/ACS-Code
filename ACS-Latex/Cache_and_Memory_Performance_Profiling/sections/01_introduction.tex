\section{Introduction}\label{sec:intro}

Every memory reference on this machine is served by one of four levels that differ by more than two
orders of magnitude in latency: a \qty{32}{\kibi\byte} per-core L1 data cache, a \qty{256}{\kibi\byte}
per-core L2, a \qty{20}{\mebi\byte} shared L3, and DDR4 DRAM. Which level a kernel hits---and how many
independent references it keeps in flight---decides its performance far more than its instruction count.
This report measures that hierarchy on the Intel i9-10900F with purpose-built microbenchmarks, reads
user-space hardware counters through \code{perf_event_open}, and interprets the numbers with AMAT and
Little's Law.

This report answers:
\begin{enumerate}
  \item What is the zero-queue access latency of each level, and how do latency and bandwidth change with
        access pattern, access size and read/write mix? (\cref{sec:zero-queue,sec:pattern,sec:rw-mix})
  \item Where does added concurrency stop buying throughput and start costing latency, and does Little's
        Law hold with measured latency? (\cref{sec:intensity})
  \item How do working-set size, cache misses and TLB misses show up in counters and runtime?
        (\cref{sec:working-set,sec:cache-miss,sec:tlb})
  \item Which benchmark mistake produces misleading numbers? (\cref{sec:pitfall})
\end{enumerate}

\paragraph{Summary of findings.} Every number below is generated from the processed data
(\code{data/summary.csv}, \cref{app:repro}). Zero-queue latency is \valqty{zq_L1_ns}{\nano\second}
(\valnum{zq_L1_cyc}~cycles) in L1, \valqty{zq_L2_ns}{\nano\second} (\valnum{zq_L2_cyc}~cycles) on the
L2 plateau, \valqty{zq_L3_ns}{\nano\second} in L3 and \valqty{zq_DRAM_ns}{\nano\second}
(\valnum{zq_DRAM_cyc}~cycles) in DRAM; an independently built cross-check agrees within
\val{zq_DRAM_xdiff}\% on DRAM. Under load, the probe's latency reaches twice its unloaded value at
\valqty{int_knee_gib}{\gibi\byte\per\second}, against a \valqty{int_peak_gib}{\gibi\byte\per\second}
ceiling; beyond the knee, extra cores buy little bandwidth but a lot of latency. Little's Law with the
measured loaded latency gives \valnum{int_knee_lines} lines in flight at the knee, while a single core
keeps at most \valnum{mlp_t1_Lmem_max} random demand misses in flight---below its fill-buffer count---so
several cores are needed to fill the pipe. Random SAXPY runs \valnum{cm_rand_span}$\times$ slower per element once
its footprint reaches DRAM, versus \valnum{cm_seq_span}$\times$ for sequential order, and an AMAT model
fitted to the counters attributes this to DRAM misses whose effective cost is
\valqty{amat_rand_aD}{\nano\second} each---the zero-queue latency divided by \valnum{amat_rand_mlp}-way
memory-level parallelism. Finally, a one-line change of working-set size turns a
\valqty{pit_dram_lo}{\gibi\byte\per\second} DRAM result into a fictitious
\valqty{pit_small_gib}{\gibi\byte\per\second} ``bandwidth'' that is really L1 reuse (\cref{sec:pitfall}).
